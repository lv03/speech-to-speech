# 语音→语音 首音频延迟实测（2026-09-07）

> 环境：macOS 15.1 arm64；本仓库 `.venv`(py3.11) + mlx；DeepSeek v4-flash API（openai 兼容，默认思考模式）。
> 口径：**模型热**；问题新问（检索未命中 SQLite 缓存）；各段串行独立测量，总端到端 = 各段实测值相加（真实语音管线有并行/流式重叠，实际可能更低）。
> 未含环节：麦克风采集 + VAD 端点判定（shell 无真实说话人，用 TTS 合成音频喂 ASR）。

## 三档端到端（串行相加；模型热、新问题、无缓存）

| 档 | C 检索实测（daemon 热） | 端到端 ≈ A+B+C+D+Δ句+F |
|---|---|---|
| 向量 vec-only | ~0.25s（daemon 80–110ms + 链路） | 0.2(A 取 parakeet 0.1–1.0 区间代表 0.2)+1.45(B 决策完成)+0.25+0.885+0.255+0.552 ≈ **3.6s** |

对照：闲聊（不检索、单轮）≈ A + B单次+ D + F ≈ 0.2+1.45+0.885+0.552 ≈ **3.1s**（若 B 用 TTFT 444ms 非决策完成，可低至 ~2.3s）。

## 主要可优化点（按收益排序）
1. **B 轮等待决策完成 1450ms**：流式里参数一收齐即可执行工具，不必等 finish_reason → 省 ~0.5–1s
2. **C 混合/完整首问 2.5s**：全部来自 rerank+扩展；命中缓存后 0.1s；预热开关默认开即为此
3. **A 端点判定**：以上是文件解码；真实流式应把 STT 延迟藏进说话时间（未测麦克风）
4. **并行化**：若 TTS 按短句边生成边播，F 首块 552ms 可与 D 后文生成重叠
