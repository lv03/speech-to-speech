## A1 语音数字基础

### 概念（背熟）

| 术语 | 含义 |
|---|---|
| **采样率** | 每秒采样点数（Hz）。16kHz = 每秒 16000 个采样点 |
| **位深** | 每个采样点的量化精度。16bit = 65536 级（-32768 ~ 32767） |
| **PCM16** | 裸脉冲编码调制，16bit 有符号整数，无压缩、无头 |
| **base64** | 二进制 → 文本编码（音频在 JSON 事件里传输用），体积膨胀约 33% |

### 采样率怎么选

| 采样率 | 用途 |
|---|---|
| 8kHz | 电话语音 |
| **16kHz** | **语音识别主流**（STT 模型训练数据规格） |
| 24kHz | 更好的音质（TTS 输出常用） |
| 44.1kHz | CD 音乐 |

### 项目里的实际（要能讲）

```
客户端麦克风 ── PCM16 16kHz 单声道 base64 ──► input_audio_buffer.append（每块 1024 字节）
    │
    ▼
管线内部统一 16kHz（PIPELINE_SAMPLE_RATE = 16000）
    │  TTS 模型原生采样率不同（Qwen3/Kokoro 都出 24kHz）→ 重采样到管线 16kHz
    ▼
send loop 输出：encode_audio_chunk 按客户端请求的采样率重采样
    └─ 客户端 session.update 里 session.audio.output.format.rate 指定（demo 用 24kHz）
    └─ 未指定默认 16kHz
```

**一句话**：输入 16k 是 STT 模型规格决定的；输出 24k 是客户端可选（demo 要 24k 音质好），服务端负责采样率转换。

## A2 VAD 原理（语音活动检测）

### 概念

VAD = 判断音频里**有没有人说话** + **说话边界**在哪，把连续音频切成"回合"。

### Silero VAD v5（项目用的）

- 轻量模型，对每个 **30ms 窗口**输出语音概率（0~1）
- 关键参数（背数字）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `thresh` | 0.6 | 概率 ≥0.6 判定"进入语音" |
| （滞回） | 0.45 | 已触发后概率 ≥0.45 就算"保持语音"（threshold-0.15） |
| `min_silence_ms` | 64 | 连续静音 ≥64ms → 判定回合结束 |
| `min_speech_ms` | 384 | 有效语音最短 384ms（过滤噪声误触发） |
| `speech_pad_ms` | 500 | 触发前保留 ≤500ms 音频并入段头（防切音） |

### 双阈值滞回（为什么要两个阈值）

```
进入语音需要高置信度 (≥0.6)，保持语音只需中置信度 (≥0.45)
→ 防止在阈值附近抖动导致反复触发/退出
```

### 项目里的演进（加分点）

- 基础 VAD 只靠静音时长判"说完"→ 语速慢/停顿多会误判
- 叠加 **Smart Turn 分类器**（本地 ONNX）：语音结束后判断"这句话是不是真的说完了"
  - 说完 → 短宽限（800ms）快速响应
  - 没说完 → 长宽限（2s）+ 延迟 STT/LLM 处理（给用户补话时间）
- 短段拼接（short_segment_merge_ms）：`min_silence_ms` 很小时一句话被切碎 → 暂存短段、间隙小就拼回（补零还原声学间隙）

## A3 ASR 渐进式转写

### 概念

- **传统（final only）**：用户说完一整段，STT 转写一次 → 延迟 = 说话时长 + 推理时长
- **渐进式（progressive）**：说话过程中周期性转写（实时字幕），说完再出最终结果

### 项目实现（SmartProgressiveStreaming）

```
每 500ms 发一次部分转写
  │
  ├─ 窗口 ≤15s：重转写整个窗口（上下文充分，准确率高）
  │
  └─ 窗口 >15s：句子感知滑动
      ├─ 已完成的句子 → "固定"（fixed_sentences，不会再变）
      └─ 只重转写固定点之后的活跃窗口（控制计算量）
```

### 关键：固定句子复用（"零重复推理"）

```
用户说话中：progressive 转写把已确认句子固定（fixed_end_time 标记）
用户说完：final 转写只对 fixed_end_time 之后的【新增音频】推理
        → 拼接固定句子 + 新转写 = 完整结果
        → 说完瞬间出结果，不重复算已确认部分
```

### 两种实现（面试可对比）

| | parakeet-tdt | paraformer |
|---|---|---|
| 渐进式 | ✅ 智能增量（固定句子复用） | ✅ 朴素（每次全量重算） |
| 计算量随时长 | 基本恒定（窗口封顶 15s） | 线性增长 |
| final 复用 | ✅ | ❌（final 再全量跑一遍） |

## A4 TTS 三种变体（Qwen3-TTS）

| 变体 | 音色来源 | 适用 |
|---|---|---|
| **Base** | 必须给参考音频（ref_audio）**声音克隆**，或缓存向量（ref_spk/ref_rvq） | 定制音色 |
| **CustomVoice** | 模型预置 speaker（默认 Aiden），直接选 | 开箱即用 |
| **VoiceDesign** | `instruct` 自然语言指令（如"欢快一点、语速稍快"） | 控语调/情绪/风格 |

**会话级动态切换**：客户端 `session.audio.output.voice` 字段 → 服务端 `_apply_session_voice_override`：
- CustomVoice → 必须是支持的 speaker 名（大小写不敏感）
- Base（克隆）→ 传音频文件路径换参考音色

**模型格式注意**：Apple Silicon 走 mlx-audio 需要 **MLX 转换权重**（`-6bit` 后缀），不能直接用 HF safetensors。

## A5 音频处理细节（链路里的工程细节）

| 处理 | 细节 |
|---|---|
| **静音修剪** | 掐掉合成音频头部静音 ramp（阈值 0.01），但**保留 40ms preroll**——防切掉"好"这种软辅音开头 |
| **重采样** | `resample_poly`（polyphase 高质量）；Qwen3/Kokoro 24kHz → 管线 16kHz（up=2/down=3） |
| **切块** | 按 `blocksize=512` 样本切块（32ms/块），余数 leftover 拼到下一块，最后不足补零 |
| **攒批发送** | send loop 把音频攒满 `MAX_AUDIO_BATCH_BYTES=6400B` 再发——减少 WebSocket 帧数（每帧都有开销） |
| **输入切块** | 客户端 append 每块 1024 字节（512 样本 × 2 字节）——对应 VAD 的 30ms 窗口粒度 |
